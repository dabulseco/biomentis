# On-demand Code Review Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A "Code Review" button under every piece of code the app shows, which has a dedicated Ollama model review that code and always return a corrected, self-contained script; plus a longer code window for the automatic reviewer and a code check in the self-critic.

**Architecture:** A pure core (`biomentis/code_review.py`: request/result types, prompt, parsing, one-retry review call) under a small job layer (`biomentis/code_review_jobs.py`: thread pool, content-keyed store, `runs/<run_id>.reviews.jsonl` sidecars). One Streamlit component (`biomentis/ui_code_review.py`) renders the button, polls pending reviews with `st.fragment(run_every=...)`, and shows the report; it is dropped into the four places code is rendered. The agent loop and the run journal are not touched.

**Tech Stack:** Python 3.11, Streamlit 1.59.2 (`st.fragment`, `AppTest`), LangChain chat models via `biomentis.llm.get_llm`, Ollama (cloud + local).

**Spec:** `docs/superpowers/specs/2026-11-01-code-review-design.md`

## Global Constraints

- Python: `/opt/anaconda3/envs/biomni/bin/python`; tests are plain scripts with the `_check()` harness, run as `$P -m biomentis.agent.tests.<name>` with `PYTHONPATH` = repo root. No pytest.
- No new third-party packages (CLAUDE.md: prefer built-in Streamlit elements; no community components).
- `runs/<run_id>.jsonl` is written only by the run's producer thread. Reviews go to `runs/<run_id>.reviews.jsonl`.
- A review click must never pause, advance, or interrupt an agent run.
- Code sent for review: whole block up to 40,000 chars; earlier-run context up to 30,000 (head-and-tail clipped); output up to 8,000.
- Worker pool: 2 concurrent reviews per process. Review call timeout: 5 minutes. One retry when the reply has no usable `corrected_code` or is not JSON.
- Verdicts: exactly `"ok" | "run_with_fixes" | "do_not_trust"`. Issue kinds: `"bug" | "mismatch" | "units" | "science" | "portability"`. Severities: `"high" | "medium" | "low"`.
- Corrected script header comment: generated by Code Review, the model name, the date, and "check before use".
- Model setting lists Ollama models only (cloud and local), no "off" entry, in the main sidebar.
- `DEFAULT_CODE_REVIEW_MODEL = "gpt-oss:120b-cloud"` (winner of the model comparison, spec "Model comparison results").

## Review Focus

1. **No Ollama key, or quota exhausted** → the panel shows the error and a "Try again" button; nothing else on the page changes. (Task 3 test `test_call_failure_is_an_error_review`; Task 6 test `test_error_panel_offers_retry`.)
2. **Reply that is not JSON, JSON without `corrected_code`, or a corrected script that does not parse** → retried once, then shown as a report with "no corrected script could be produced". (Task 2 test `test_retry_once_then_report`.)
3. **Another widget clicked while a review is pending** → the review still completes and appears on a later rerun. (Task 3 test `test_job_survives_without_caller`; Task 6 test `test_pending_review_appears_after_rerun`.)
4. **Code entries replayed from runs recorded before this change (no `run_id`/`block_index`)** → review with code-and-output context only, no crash. (Task 4 test `test_old_entry_without_locator`.)
5. **Non-Python blocks (Bash `#!BASH`, R `#!R`) and blocks over 40,000 chars** → prompt names the language and asks for a corrected script in that language; oversize code is head-and-tail clipped with a note. (Task 2 tests `test_language_in_prompt`, `test_oversize_code_clipped`.)
