# What I'd Recommend

A follow-up cleanup pass derived from the project status review (`status_20260718.md`).

## 1. Delete the legacy v0 agent stack

These four files are the pre-`A1` ReAct agent. `A1` does the ReAct work directly via langgraph, and the new code path doesn't import any of them. Their only callers are the biorxiv scripts (see #2).

- `biomni/agent/react.py`
- `biomni/agent/qa_llm.py`
- `biomni/agent/function_generator.py`
- `biomni/agent/env_collection.py` ← **already broken**: it does `from biomentis.agent.base_agent import base_agent`, but no such module exists. The file can't even be imported.

**Before deleting**, confirm with `grep -rn "from biomentis.agent.react\|from biomentis.agent.qa_llm\|from biomentis.agent.function_generator\|from biomentis.agent.env_collection" .` that nothing outside `biorxiv_scripts/` uses them.

## 2. Delete or quarantine `biomni/biorxiv_scripts/`

The directory contains three scripts (`extract_biorxiv_tasks.py`, `generate_function.py`, `process_all_subjects.py`) used to mine bioRxiv papers and regenerate tool descriptions. They are **data-prep tooling**, not part of the agent or the UI.

Two options:
- **Delete** if the maintainers are no longer refreshing the tool catalog from bioRxiv.
- **Move to `scripts/`** at the repo root and add a one-paragraph docstring explaining when to run them (e.g. "only when contributing new tool descriptions via the bioRxiv mining pipeline"). Right now they live under `biomni/` which implies they ship with the package — they don't.

## 3. Delete the legacy `biomni_env/` directory

After the install-path collapse, `requirements.txt` is canonical and `quick_start_guide.md` no longer references the conda envs. The directory is already marked "legacy / not the recommended path" in its own README.

What to remove:
- `biomni_env/setup.sh`
- `biomni_env/install_cli_tools.sh`
- `biomni_env/install_r_packages.R`
- `biomni_env/r_packages.yml`
- `biomni_env/cli_tools_config.json`
- `biomni_env/setup_path.sh`
- `biomni_env/environment.yml`
- `biomni_env/fixed_env.yml`
- `biomni_env/bio_env.yml`
- `biomni_env/bio_env_py310.yml`
- `biomni_env/new_software_v008.sh`
- `biomni_env/README.md` (the directory itself)

**Exception**: if anyone is still using `bio_env_py310.yml` for `cnvkit` (the only Python-3.10-only tool in the catalog), keep just that one file and document it in `quick_start_guide.md`'s troubleshooting section as a sidecar install.

## 4. Investigate `biomni/tool/protocols.py`

There's a tool description at `biomni/tool/tool_description/protocols.py` that says it reads local files from `biomni/tool/protocols/`, but `read_module2api` only loads the description module — the actual implementation file isn't wired into the runtime tool discovery. The `biomni/tool/protocols/` directory is effectively empty (just an `__init__.py`).

Pick one:
- **Remove both** (`tool/protocols.py` and `tool_description/protocols.py`) if local-protocol reading isn't a feature you want.
- **Add the implementation** with a proper `@register_tool` decorator and an `__init__.py` that re-exports it, so the LLM can actually call it.

## 5. Decide on `biomni/tool/__init__.py`

The file currently just re-exports `get_tool_decorated_functions` and is never triggered — the live app imports `biomni.tool.support_tools` and `biomni.tool.tool_registry` directly, and `read_module2api` imports `biomni.tool.tool_description.*` directly.

Two options:
- **Make it real**: have `tool/__init__.py` auto-discover all `@register_tool`-decorated functions from every `biomni/tool/*.py` module and re-export them, so `from biomentis.tool import analyze_data` actually works (right now it doesn't).
- **Delete it** if the user-facing entry is `A1.go("…")` and the tool API is internal.

## 6. Decide on `task/`, `eval/`, `biorxiv_scripts/`

These three are independent of the agent and only used by people running the benchmark or refreshing the tool catalog.

- If you intend to support the `BiomniEval1` benchmark going forward: keep `biomni/task/{base_task,hle,lab_bench}.py` and `biomni/eval/biomni_eval1.py`, but add a short `docs/eval.md` showing how to run it.
- If not: delete the directories. The `a1.py:187` reference to `hle` should also go.

## 7. Regenerate or delete `DETAILS.md`

The file is auto-generated by an external tool (Detailer) and is already out of date — it doesn't list `ui_core.py`, `ollama_utils.py`, `config.py`, the `know_how/` package, or any of the tool modules added since it was generated. It will continue to drift.

Two options:
- **Delete it** and rely on the Sphinx docs in `docs/` plus the in-repo READMEs.
- **Regenerate it from a CI step** on every push so it can't go stale.

4. #3 — delete `biomni_env/`. Re-run verification.
